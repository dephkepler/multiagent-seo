# Захар Палыч — Deploy

Прод-раскатка.

Настоящий runbook — `doc/abalisbotlead/vps-deploy.md` (несмотря на имя файла, это единственный
реальный прод-раннбук — Abalis-бот не отдельный продукт, а фича внутри этого же backend'а, вся
инфра одна). `doc/deploy/deploy.md` — заглушка про несуществующий хост, не источник правды.

Прод: `132.243.194.137`, путь на сервере — `/opt/multiagent-seo`. Доступ — SSH-ключом, алиас
`prod-vps` уже настроен в `~/.ssh/config` на этой машине (`ssh prod-vps '<command>'`), пароль не
нужен. Этот доступ работает только с этого Мака — если задача выполняется из другого окружения
(облачная сессия, другая машина), алиаса там не будет, нужно сказать об этом пользователю, а не
изобретать альтернативный доступ.

Этот же VPS держит ещё два проекта (`tracker-bot`, `job-applier`) в полностью отдельных
docker-compose стеках — не трогай их контейнеры/файлы. Общий список всех трёх проектов и как их
деплоить — глобальная команда `/deploy` (`~/.claude/commands/deploy.md`); этот файл — только про
multiagent-seo, специфичные правила проекта ниже дополняют общую команду, а не дублируют.

## Перед стартом
1. `git status --short` и `git rev-parse --abbrev-ref HEAD` локально — если есть незакоммиченные
   изменения или ветка не та, что ожидает пользователь, **остановись и спроси**, не угадывай.
2. Спроси (если не сказано явно) объём: полный передеплой, или точечно (только backend/только
   бот-фичи).

## Шаги
1. Если нужно — закоммить/запушь (человеческий коммит-месседж, без `Co-Authored-By`/AI-футеров;
   remote — `github`, см. `git push github main`). **Не пуш, если пользователь не просил именно
   деплой сейчас.**
2. `ssh prod-vps 'cd /opt/multiagent-seo && git pull'` — покажи, что подтянулось.
3. **Точка подтверждения.** Прежде чем поднимать стек — покажи пользователю, что будет выполнено,
   и жди явного "ок". Это прод, действие трудно обратимое.
4. `ssh prod-vps 'cd /opt/multiagent-seo && docker compose -f devops/compose.yaml --env-file backend/.env up --build -d'`
   (сервер сам эту же команду знает под алиасом `dc`, но `.bashrc` в одноразовом `ssh host 'cmd'`
   не подхватывается — прописывай явно, как выше). **Не добавляй `-f devops/compose.prod.yaml`**
   без отдельного подтверждения — этот файл требует внешний volume `contentflow_postgres_data`,
   которого по документированной истории сервера никогда не было; добавишь — велик шанс что
   команда просто упадёт (или хуже, если такой volume всё же завели, а мы предполагаем неверно —
   именно поэтому не гадать, а спросить).
5. Проверить: `ssh prod-vps 'cd /opt/multiagent-seo && docker compose -f devops/compose.yaml --env-file backend/.env ps'`
   (контейнеры `multiagent-seo-app-1`, `multiagent-seo-frontend-1`, `multiagent-seo-postgres-1` —
   `Up`), затем коротко `logs --tail 50 app` — не виси в хвосте (`-f`) без причины. Публичного
   HTTPS-домена для проверки не подтверждено — не выдумывай curl-проверку по несуществующему URL.
6. Отчитайся: что задеплоено, что показала проверка. Если что-то пошло не так — см.
   `doc/abalisbotlead/vps-deploy.md` → «Грабли, на которые наступили»; не гадай фикс сам без
   совпадения с этим списком.

## Жёсткие границы
- Миграции — **не запускай в рамках этого skill'а без отдельной явной просьбы**.
- Не трогай Postgres volume/данные напрямую (`docker volume rm` и т.п.) ни при каких обстоятельствах
  без явного разрешения — необратимо.
- Credentials/токены (`backend/credentials.json`, `backend/.env`) на сервере — не логируй их
  содержимое, не выводи в чат.
- Если что-то в проверке (шаг 6) не сошлось — сообщи и остановись, не пытайся чинить прод
  самостоятельно вне этого runbook'а.
