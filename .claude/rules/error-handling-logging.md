# Error handling & logging — правила (дистиллят)

Полная версия с обоснованием (половина находок аудита — отсюда) — `doc/standards/error-handling-logging.md`.

**Принцип №0.** Ошибку логирует только внешний слой (HTTP-хендлер/middleware). Infrastructure и
application/service — только оборачивают и возвращают: `fmt.Errorf("<op>: %w", err)`. Никакого
`log.*Context(...)` прямо перед `return ...err` в не-хендлерных пакетах — иначе одна ошибка
логируется по 3 раза с разным `module` и корреляция ломается.

## Ошибки
1. Никогда не глотать ошибку через `_` на `Write`/`Encode`/`io.ReadAll`/`json.Marshal`/`rand.Read`/
   `Save`/repo/IO — присвой и обработай.
2. Сбой ≠ пустой результат. Функция не должна возвращать одинаковый `nil`/zero и на «упало», и на
   «нет данных» — верни ошибку или явный сигнал.
3. Batch `flush()` обязан возвращать ошибку. Чисть батч только при успехе; при сбое — прерывай/
   возвращай ошибку и **подавляй** success-лог. Топ-баг аудита: flush молча терял целый батч, а
   юзер видел `accepted`.
4. Error-response path: кодируй тело в буфер; при сбое маршалинга — `WriteHeader(500)` + минимальное
   статическое тело; иначе пиши буфер.

## Логирование
5. Уровни: ERROR = неожиданный actionable сбой. WARN = неожиданный, но терпимый. INFO = нормальный
   lifecycle. DEBUG = ожидаемая/graceful деградация (мок-фоллбэки, промах serp-lookup,
   auto-publish-blocked, фейлы wplogin) — **не WARN**.
6. Без PII/секретов/тел ответов в логах: сырой email, полный donor/site URL, креды, тела HTTP-
   ответов — нельзя; счётчики/id/хеши — можно. Сырой `err.Error()` в поле, уходящем в Sheets —
   сначала санитизируй (вырежи тела/паттерны кредов), потом truncate.
7. DB host/port/db name — можно логировать; user/password — нельзя.

## Enforcement
`golangci-lint` + `errcheck` в CI банит молчаливые `_ =` / `x, _ :=`. На ревью — лови
`log.*Context(...)` прямо перед `return ...err` в не-хендлерных пакетах (двойной лог).
