# Naming — правила (дистиллят)

Полная версия с объяснением и анти-примерами — `doc/standards/naming.md`.

1. Не плоди stutter через квалификатор пакета: `articles.Status`, не `articles.ArticleStatus`. Вторичные сущности — уточняй: `VariantStatus`, `RevisionSource`.
2. Одинаковое слово ≠ одинаковый тип. Разные множества значений → разные типы, не общий `Status`.
3. Перечисление — типом (`type X string` + типизированные консты), не `string` + комментарий.
4. Имя — суть/намерение, не реализация или «вообще»: `recordWriterOutcome`, `InsertVariant`, не `Insert`/`process`/`data`/`manager`.
5. Булевы — состояние/вопрос: `IsTerminal`, `enabled`, `qualityOK`. Не `flag`, `status2`.
6. Короткие имена (`i`, `r`, `s`) — только в маленькой области видимости; в длинной функции/полях — полное имя.
7. Консты одного типа — единый префикс (`StatusGenerating/StatusDraft/...`).
8. Функции/методы — глагол + объект: `generateContent`, `markFailed`. Не `process`/`handle`/`do`/`manage`/`run` в одиночку.
9. Переменные называют сущность, не тип/заглушку: `competitors`, `renderStats`. Не `data`/`info`/`tmp`/`val`/`obj`/`res`/`item`.
10. Не кодируй тип в имени (без венгерской нотации): не `strVal`/`iCount`.
11. Получатели — 1–2 буквы, одинаковые во всех методах типа (`s *Service` везде, не `s`/`svc` вперемешку).
12. Ошибки: `err` — для значения; sentinel — экспортируемая переменная с префиксом `Err` (`ErrNoCluster`).

## Чек-лист на ревью
- `package.Имя` читается без догадок и без stutter?
- перечисление типизировано?
- имя про суть, не про «как сделано» / общее `data`/`process`?
- функция — глагол+объект?
- получатель одинаков во всех методах типа?
- sentinel-ошибка с `Err`-префиксом?
